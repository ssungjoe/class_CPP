# 10주차. 객체지향을 돕는 기능들

## 1. 컴포지션과 어그리게이션 (Composition & Aggregation)

새로운 클래스를 만들 때 기존 클래스를 재사용하는 방법들이다. 이를 이해하기 위해 먼저 다중 상속의 문제점을 짚고 넘어간다.

### 1-1. 다중 상속(Multiple Inheritance) 다시 보기와 그 단점

다중 상속은 부모 클래스를 여러 개 상속받아 자식 클래스를 정의하는 기법이다. (예: `monster`와 `character`를 동시에 상속받는 `monster_a`). 안정적인 디자인 패턴을 빠르게 전파할 수 있다는 장점이 있지만, 다음과 같은 치명적인 단점들을 가진다.

1. **거대 클래스(Large Class) 문제**: 클래스가 커지고 속성과 기능이 많아져 사용하기 어려워진다. 부모 클래스가 변경되면 상속받은 모든 클래스에 영향을 미친다.
2. **높은 결합도(Coupling)**: 의존도가 높아지면 유지보수가 매우 힘들어진다.
* 💡 **객체지향 개발의 조언 (OCP 원칙)**: "수정에는 닫혀 있고, 확장에는 열려 있어야 한다.". 즉, 수정한 내용이 다른 클래스나 함수의 연쇄 수정으로 이어지지 않아야 하고(수정에 닫힘), 기능 확장은 새로운 코드를 추가하는 것만으로 쉽게 이루어져야 한다(확장에 열림).


3. **컴파일 시간 증가**: 소스 코드가 변경되면 연관된 파일들을 재컴파일해야 하는데, 결합도가 높으면 파일 하나만 수정해도 수만 개의 클래스 파일을 다시 컴파일하느라 몇 시간이 소요될 수 있다.

---

위의 단점을 해결하기 위한 대안이 상속 대신 **'멤버 변수'로 객체를 포함**시키는 컴포지션과 어그리게이션이다. 단일 속성만 가지므로 결합도가 낮아진다.

### 1-2. 컴포지션 (Composition)

* **개념**: 재사용할 속성/기능을 가진 객체를 직접 멤버 변수로 포함하는 **포함('part-of')** 관계다.
* **생명 주기 (동시 생성, 동시 소멸)**: 포함된 부분 객체는 포함한 전체 객체에 종속된다. 즉, 전체 객체가 태어날 때 부분 객체도 함께 태어나고, 죽을 때 함께 죽는다.

```cpp
class monster_a {
private:
    // 객체 자체를 직접 멤버 변수로 선언 (컴포지션)
    character main_body; 
    monster main_role;
public:
    void attack(player target_player) { main_role.attack(target_player); }
};

```

### 1-3. 어그리게이션 (Aggregation)

* **개념**: 분리된 클래스의 객체를 직접 가지지 않고 **포인터나 레퍼런스(참조)** 변수로 포함하여 사용('has-a')하는 관계다.
* **생명 주기 (단독 생성, 단독 소멸)**: 외부에서 이미 만들어진 객체를 전달받아 연결만 하므로, 전체 클래스와 부분 클래스의 생명 주기가 다르다(독립적이다).
* **늦은 바인딩(Late Binding)**: 설계 이후에도 구현체를 유연하게 바꿔서 참조할 수 있어 활용도가 매우 높다.

```cpp
class monster_b {
private:
    // 객체의 레퍼런스(참조)만 보유 (어그리게이션)
    character &main_body; 
    monster &main_role;
public:
    // 외부에서 이미 만들어진 객체를 전달받아 초기화 목록으로 연결
    monster_b(character &ref_character, monster &ref_monster) 
        : main_body(ref_character), main_role(ref_monster) {};
};

```

## 2. 가상 함수와 동적 바인딩 (Virtual Function & Dynamic Binding)

### 2-1. 가상 함수란?

* 부모 클래스로 **업캐스팅(Upcasting)** 되었을 때 호출되는 함수를 다르게 하기 위해(다형성 구현) 선언하는 함수다.
* 함수 선언 앞부분에 **`virtual`** 키워드를 추가하며, 자식 클래스에서 오버라이딩(재정의)할 때는 끝에 **`override`** 키워드를 추가한다.
* 일반 함수로 오버라이딩하면, 업캐스팅 후 포인터로 호출 시 무조건 '부모 클래스의 함수'가 호출되어 버린다. 가상 함수로 정의해야만 실제 들어있는 '자식 클래스'의 함수가 정상 호출된다.

### 2-2. 정적 바인딩 (Static Binding)

* 바인딩이란 함수 호출 코드가 실제 실행될 메모리 주소 코드와 연결되는 과정이다.
* **동작 시점**: **컴파일 시점**에 결정된다.
* 💡 **오해 주의**: 항상 같은 메모리 '주소'로 고정된다는 뜻이 아니다. 프로그램 실행마다 실제 주소는 달라지지만, **"어느 대상(함수)을 호출할지" 그 위치 정보가 컴파일 시점에 변함없이 고정**된다는 의미다. 일반 변수, 함수, 정적 멤버가 이에 해당한다.

### 2-3. 동적 바인딩 (Dynamic Binding)

* **동작 시점**: 대상이 **프로그램 실행(Runtime) 시점**에 동적으로 결정되며 수시로 변경될 수 있다. 가상 함수가 대표적인 예다.
* **메모리 이동 단계**: 정적 바인딩처럼 대상 함수의 주소로 다이렉트로 직행하는 것이 아니라, 중간 경유지를 거친다. 즉, 포인터에 저장된 **원래 객체의 주소로 먼저 이동한 후 $\rightarrow$ 그 객체의 가상 함수 멤버 주소를 찾아내어 이동**한다.

### 2-4. 가상 함수 테이블 (vtable)과 포인터 (`_vfptr`)

가상 함수를 동적으로 호출할 수 있는 내부 원리다.

1. **가상 함수 테이블 (vtable)**: 최상위 클래스부터 가상 함수들의 실제 주소를 모아둔 표다. 업캐스팅 후에도 자식의 함수가 호출되도록 매핑 정보를 제공한다.
2. **`_vfptr` 포인터**: 가상 함수가 포함된 객체를 생성하면, 객체 내부에 몰래 가상 함수 테이블을 가리키는 `_vfptr` 포인터가 생성된다. 이 포인터를 통해 런타임에 올바른 함수를 찾아간다.

## 3. 순수 가상 함수와 가상 소멸자

### 3-1. 순수 가상 함수 (Pure Virtual Function)

* **개념**: 부모 클래스에서는 함수 내용물(정의) 없이 선언만 해두고, **상속받는 자식 클래스에게 무조건 오버라이딩(재정의)을 강제**하는 문법이다.
* **문법**: 함수 선언 끝에 `= 0;`을 붙인다 (`virtual void attack_at_dawn() = 0;`).
* **의의**: 자식 개발자에게 "이 함수는 무조건 오버라이딩하라"고 문법적으로 강제한다. 안 하면 컴파일 오류가 발생하여 프로그램이 실행조차 되지 않는다. 일반 가상 함수는 오버라이딩을 생략해도 부모의 코드가 실행되지만, 순수 가상 함수는 생략이 불가하다.

### 3-2. ⚠️ 가상 소멸자 (Virtual Destructor)의 치명적 중요성

생성자는 부모 $\rightarrow$ 자식 순으로 호출되고, 소멸자는 자식 $\rightarrow$ 부모 순으로 역순 호출된다.

* **문제점**: 만약 부모 클래스 포인터로 업캐스팅된 자식 객체를 `delete` 할 경우, 일반 소멸자를 쓰면 컴파일러는 껍데기만 보고 **부모의 소멸자만 달랑 호출**해버린다. 이로 인해 자식 객체가 내부에서 동적 할당한 리소스들이 해제되지 않아 끔찍한 메모리 누수(Memory Leak)가 발생한다.
* **해결책**: 반드시 부모 클래스의 소멸자에 **`virtual`** 키워드를 붙여야 한다. 그래야 다형성이 적용되어 자식의 소멸자가 먼저 정상적으로 호출된 후 부모 소멸자가 호출된다.

## 4. 추상 클래스와 정적 멤버

### 4-1. 추상 클래스 (Abstract Class)와 구상 클래스 (Concrete Class)

* **추상 클래스**: **순수 가상 함수를 1개 이상 포함**하고 있어 완전히 구체화되지 않은 클래스다. 이 클래스 자체로는 **절대 인스턴스(객체)를 선언할 수 없다**. (`new monster()` 불가). 다형성 구현의 뼈대 역할을 한다.
* **구상 클래스**: 추상 클래스를 상속받아 모든 순수 가상 함수를 완벽히 오버라이딩하여 구체화한 일반 클래스다.

> 💡 **전략 패턴 (Strategy Pattern)**
> <br>공통된 흐름(예: 부모 포인터로 `find_route()` 호출) 속에 알고리즘만 갈아 끼우고 싶을 때 사용한다. 사용하는 쪽에서는 실제 알고리즘 구현을 몰라도 되며, 유지보수성이 극대화된다.

> 💡 **더 알아보기: C++의 `__interface` 키워드**
> <br>C++ 표준에는 자바의 '인터페이스'라는 독립된 문법이 없지만, 추상 클래스로 똑같이 구현할 수 있다. 단, 비주얼 스튜디오에서는 **`__interface`** 키워드를 제공하며, 이를 쓰면 내부에 `= 0`을 붙이지 않아도 자동으로 모든 함수가 순수 가상 함수로 취급된다.

### 4-2. 정적 멤버 (Static Member)

`static` 키워드가 붙으며, 특정 객체(인스턴스)에 종속되지 않고 **해당 클래스로 만들어진 모든 객체가 하나를 공유**한다.

* **선언과 초기화**: 메모리에 클래스당 딱 한 번만 할당되므로, 선언은 클래스 안에 하되 **초기화는 반드시 클래스 바깥(전역 범위)에서 단 한 번 해주어야 한다** (`int monster::mon_count = 0;`).
* **호출**: 객체를 안 만들고도 `클래스명::함수명()`으로 즉시 호출할 수 있다.
* **사용처**: 공유 변수 관리, 유틸리티 함수(수학 행렬 연산 등), **객체를 내부에서 찍어내는 팩토리 패턴(Factory Pattern)** 등에 널리 쓰인다.

### 4-3. 활용 예제: 팩토리 패턴과 리팩토링

커피점 예제에서, `main` 함수가 직접 자식 객체를 `new`로 만들지 않고, 추상 부모 클래스인 `all_coffee_shop`의 **정적 함수(`create_coffee_shop`)에게 숫자를 넘겨 알맞은 객체 생성을 위임**하는 기법이다.
이처럼 동일한 결과물이 나오되 코드 구조를 유연하고 효율적으로 바꾸는 작업을 리팩토링(Refactoring)이라고 한다.
