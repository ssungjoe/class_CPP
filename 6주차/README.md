# 6주차. 객체지향과 클래스 (C++ 핵심 패러다임)

<br>

## 1\. 객체지향 이전의 프로그래밍 패러다임

프로그래밍 패러다임이란 프로그램을 어떤 절차와 구조로 만들 것인지에 대한 접근 방법이다.

### 1-1. 비구조적 프로그래밍

- 코드를 구조화하지 않고 첫 번째 줄부터 마지막 줄까지 차례대로 실행하는 방식이다.
- 코드의 흐름을 강제로 이동하는 `goto` 문을 주로 사용하며, 초창기 포트란이나 어셈블리어가 이에 해당한다.

### 1-2. 절차적 프로그래밍과 하향식(Top-down) 접근

- 소스 코드를 논리적 기능 단위인 '**프로시저(Procedure, 함수)**'로 묶어서 구조화하는 방식이다 (C언어, 코볼 등).
- **흐름 코드와 프로시저 뭉치**: 프로그램의 중심 흐름을 담당하는 메인 코드와, 그 메인에서 필요할 때마다 호출해 쓰는 프로시저 뭉치들로 분리하여 관리한다.
- **하향식(Top-down) 접근법**: 전체 기능을 모두 파악한 후, 이를 구현하기 위해 작은 단위(프로시저)로 쪼개어 내려가는 방식이다. 전체 기능이 변경되면 하위 세부 단위도 뜯어고쳐야 하므로 변화에 대응하기 어렵다.

### 1-3. 절차적 프로그래밍의 치명적 문제점

규모가 커질수록 다음과 같은 치명적인 한계가 발생한다.

1.  **전역 변수 접근 제어 실패**: 프로시저 간에 데이터를 주고받기 위해 전역 변수를 쓰게 되는데, 모든 곳에서 이 전역 변수에 접근할 수 있어 불필요한 정보가 노출되고 잘못 수정할 경우 프로그램에 치명적인 에러가 발생한다.
2.  **계층 구조 파악의 어려움**: 하위 프로시저를 아무 곳에서나 무분별하게 직접 호출할 수 있어, 코드가 꼬이고 계층 구조를 파악하기 힘들어진다.
3.  **현실 모델링 한계**: 현실의 사물들이 가진 복잡한 다층 구조를 프로그래밍 내부의 '순차적 흐름'만으로 표현하는 데 무리가 있다.

<br>

## 2\. 객체지향 프로그래밍 (OOP)과 상향식(Bottom-up)

위의 문제를 해결하기 위해 등장한 패러다임이다. 데이터(속성)와 함수(기능)를 하나로 묶은 '**객체(Object)**'를 바탕으로, 객체 간의 관계를 소스 코드로 구성한다.

- **상향식(Bottom-up) 접근법**: 전체 기능을 다 모르더라도 개별적인 단위(객체)를 먼저 만들어 두고, 레고 블록을 조립하듯 차곡차곡 쌓아 올려 전체 프로그램을 완성하는 방식이다. 전체가 바뀌어도 일부 객체만 교체하면 되므로 유지보수에 매우 유리하다.

### 2-1. 현실 세계 모델링과 객체 간의 관계

현실 세계의 대상이 가진 특징과 관계를 논리적으로 구조화(모델링)한다.

- **포함 관계 (Has-a)**: 동력 장치가 가솔린 엔진, 바퀴, 가속 페달 등을 '포함'하고 있는 관계다.
- **상속 관계 (Is-a)**: "가솔린 엔진은 엔진이다"처럼 부모-자식 간의 관계다.
- **사용 관계 (실선 화살표)**: 가솔린 엔진이 미션과 바퀴에 동력을 전달하듯, 한 객체가 다른 객체를 사용하는 종속적인 관계다.
- **이벤트 사용 관계 (점선 화살표)**: 객체를 직접 조작하지 않고, 특정 사건(이벤트)을 발생시켜 간접적으로 제어하는 방식이다 (예: 가속 페달을 밟으면 출력 조절기에 신호가 감).
- **접근 제어 (O, X 표시)**: 가속 페달이 엔진 내부의 피스톤을 직접 건드리지 못하게 논리적으로 접근을 막는(X) 설계다.

## 3\. 객체지향 프로그래밍의 4가지 핵심 특징

### ① 추상화 (Abstraction)

집단의 불필요한 요소는 배제하고 **'공통된 핵심 특징'만 추출**하는 것이다.

- 가솔린, 디젤, 가스의 차이를 버리고 "연료를 연소시켜 동력을 얻는다"는 특징만 뽑아 '내연기관 엔진'이라는 추상화된 대표 객체를 만든다.

### ② 캡슐화 (Encapsulation)

복잡한 내부 기능을 묶어 **단순화**하여 동작하게 함으로써 외부에서 불필요한 정보를 감추는 것이다.

- **은닉화와의 차이점**: 단순히 남이 못 보게 감추기만 하는 것은 '은닉화'이고, 복잡한 부품(피스톤, 밸브 등)을 보이지 않는 껍데기로 묶은 뒤 '가속'이라는 단순한 버튼 하나만 외부에 제공하는 것이 '캡슐화'다.

### ③ 상속성 (Inheritance)

추상화된 대표 객체(부모)의 특성을 그대로 이어받아, 거기에 새로운 특성을 추가하여 파생 객체(자식)를 만드는 것이다.

- **일반화(Generalization)와의 차이점**: 프로그램상의 동작은 똑같다. 다만 의미론적으로, 밑에서 위로 공통점을 뽑아내어 대표 객체를 만드는 과정을 '일반화'라고 하고, 위에서 아래로 특성을 물려받아 파생 객체를 만드는 것을 '상속'이라고 부른다.

### ④ 다형성 (Polymorphism)

부모 객체의 특성을 상속받은 자식 객체는 부모의 자리를 **대체(대입)**할 수 있으나, 그 세부적인 동작은 자식 객체 자신만의 특성에 맞춰 **각기 다르게 동작**하는 성질이다.

- 내연기관 엔진과 전기 엔진은 모두 '엔진'을 대체할 수 있지만, 하나는 연료를 태우고 하나는 모터를 돌리는 식으로 완전히 다르게 동작한다.

## 4\. 클래스와 인스턴스 (C++ 문법)

- **객체(Object) = 클래스(Class)**: 객체지향에서 이 둘은 본질적으로 데이터와 함수를 포함하는 논리적 단위를 뜻한다.
- **클래스**: 객체를 만들어내기 위해 변수와 함수를 정의해 둔 '**문법적인 틀(설계도)**'이다.
- **인스턴스(객체)**: 클래스라는 틀을 이용해 실제 메모리에 할당하여 사용할 수 있게 만든 '**실체(변수)**'다.

### 4-1. C++ 클래스 정의 문법

클래스는 크게 외형을 잡는 '**클래스 선언부**'와 내부 로직을 짜는 '**멤버 함수 정의부**'로 나뉜다.

```cpp
// [1] 클래스 선언부
// 부모 클래스를 상속받을 때는 콜론(:) 뒤에 접근 지정자와 부모 이름을 쓴다.
class gs_engine : public ic_engine {
public: // 접근 지정자: 외부에서 마음대로 접근 가능한 영역
    gs_engine();  // 생성자: 객체가 생성될 때 자동 호출되는 특수 함수
    ~gs_engine(); // 소멸자: 객체가 소멸될 때 자동 호출되는 특수 함수

    // 짧은 함수는 선언부에서 바로 중괄호{}를 열고 구현하기도 한다.
    int get_current_fuel() { return current_fuel; };

private: // 접근 지정자: 외부 접근을 철저히 막고, 클래스 내부에서만 사용하는 영역
    void acceleration_output() override; // 멤버 함수 선언
    void increasing_fuel() { increasing_piston_speed(); };
    void increasing_piston_speed() {};

    int current_fuel; // 멤버 변수
    int piston_speed;
}; // 반드시 세미콜론으로 닫아야 함

// [2] 멤버 함수 정의부
// 외부에서 함수를 따로 구현할 때는 '클래스명::함수명' 형태의 네임스페이스를 사용한다.
void gs_engine::acceleration_output() {
    increasing_fuel();
    current_fuel++;
}
```

### 4-2. 객체의 선언과 메모리 할당

C++에서는 클래스를 일반 변수처럼 스택에 올릴 수도 있고, `new` 키워드를 써서 힙(Heap) 영역에 동적으로 할당할 수도 있다. 이에 따라 접근하는 연산자가 달라진다.

```cpp
int main() {
    // 1. 정적 객체 선언 (일반 변수처럼 선언)
    gs_engine my_engine;

    // 정적 선언된 객체는 점(.) 기호를 사용하여 내부 멤버에 접근한다.
    my_engine.increasing_piston_speed();

    // ---------------------------------------------------------

    // 2. 동적 객체 선언 (new 키워드와 포인터 사용)
    gs_engine *my_engine_pointer = new gs_engine();

    // 포인터로 생성된 동적 객체는 화살표(->) 기호를 사용하여 접근해야 한다!
    int fuel = my_engine_pointer->get_current_fuel();

    // new로 동적 할당한 객체는 반드시 delete를 사용해 메모리를 직접 해제해야 한다.
    delete my_engine_pointer;

    return 0;
}
```
